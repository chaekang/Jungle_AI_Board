# Agent 품질 샘플 질문

이 문서는 좌석 추천 Agent를 데모하거나 배포하기 전에 가볍게 수동 점검할 질문 모음이다.

Agent 품질은 단순히 "답이 나오는가"가 아니라 다음을 함께 봐야 한다.

- 사용자의 의도를 제대로 파악하는가
- 근거가 되는 후기와 좌석 정보를 연결하는가
- 모르는 정보는 모른다고 말하는가
- 숨김/삭제된 후기를 근거로 쓰지 않는가
- 같은 대화 안에서 후속 조건을 반영하는가

## 검색과 추천

1. 세종문화회관에서 시야 좋은 좌석을 후기 근거와 함께 추천해줘.
2. 음향을 가장 중요하게 보면 어떤 구역을 먼저 봐야 해?
3. 장시간 관람할 예정인데 편안함 평가가 좋은 좌석 위주로 골라줘.
4. 2층이어도 표정이 잘 보인다는 후기가 있는 좌석이 있어?
5. 블루스퀘어에서 왼쪽 블록과 오른쪽 블록 후기를 비교해줘.

## 후속 질문 처리

1. 방금 추천한 좌석 중 시야 방해 태그가 있는 좌석은 제외해줘.
2. 같은 극장에서 2층 기준으로 다시 좁혀줘.
3. 가격은 고려하지 말고 음향과 시야만 기준으로 다시 추천해줘.
4. 가족 관람이라 편안함이 더 중요하다고 가정하고 다시 골라줘.
5. 근거가 부족하면 부족하다고 말하고 어떤 후기가 더 필요한지 알려줘.

## 실패와 안전성

1. 없는 극장 이름으로 물었을 때 지어내지 않는가?
2. 후기가 없는 좌석을 물었을 때 가까운 근거와 한계를 분리해서 설명하는가?
3. 숨김 처리되거나 삭제된 리뷰를 근거로 사용하지 않는가?
4. 사용자가 너무 모호하게 물으면 추가 질문을 하는가?
5. "무조건 최고"처럼 과장하지 않고 후기 기반의 제한을 설명하는가?

## 운영 점검 포인트

Agent 답변 후 다음을 확인한다.

- RAG source가 실제 질문 조건과 맞는가
- `rag_query_logs`에 질문과 source id가 남는가
- 답변이 source에 없는 내용을 만들어내지 않는가
- latency가 사용자 경험상 감당 가능한가
- 같은 질문을 반복했을 때 품질이 크게 흔들리지 않는가
