# RAG 품질 평가 질문

이 문서는 RAG embedding을 다시 만들거나 prompt, metadata, 필터 파싱을 바꾼 뒤 수동으로 확인할 질문 모음이다.

질문마다 다음을 확인한다.

- 선택된 source가 질문과 맞는가
- 답변이 확실한 정보와 불확실한 정보를 구분하는가
- 극장, 좌석, 작품, 태그 필터가 올바르게 파싱되는가
- 숨김 처리되거나 삭제된 후기가 근거로 사용되지 않는가
- `rag_query_logs`에 질문, 필터, source id, 답변 preview, latency가 남는가

## 좌석 조회

1. 세종문화회관 2층 A구역 7번 시야는 어때?
2. TOM 1관 1층 10번 좌석은 소리가 괜찮아?
3. 블루스퀘어 왼쪽 블록에서 무대 전체가 잘 보여?
4. 샤롯데씨어터 3층 중앙 좌석 후기가 있으면 장단점을 알려줘.
5. 같은 극장 안에서 1층과 2층 시야 차이를 후기 근거로 비교해줘.

## 시야 방해와 조건 필터

1. 세종문화회관에서 시야 방해가 있다는 후기는 어느 좌석 범위에 많아?
2. 2층에서 시야 방해 태그가 붙은 후기는 어디까지 있어?
3. 특정 구역이 아니라 전체 기준으로 방해가 많은 좌석 범위를 알려줘.
4. "기둥", "난간", "앞사람" 같은 표현이 있는 후기를 구분해서 설명해줘.
5. 숨김 처리된 후기나 삭제된 후기가 답변 근거에 들어가지 않는지 확인해줘.

## 의도 품질

1. 배우 표정이 잘 보이는 좌석을 후기 근거와 함께 추천해줘.
2. 음향을 중요하게 보는 사람에게 맞는 좌석을 찾아줘.
3. 시야 좋은 좌석과 음향 좋은 좌석이 다르면 근거를 나눠서 설명해줘.
4. 장시간 관람이라 편안함이 중요한데 어떤 좌석이 좋아?
5. 가격 대비 만족도가 높아 보이는 좌석을 근거와 함께 알려줘.

## 실패 사례

1. 없는 극장 이름으로 물었을 때 모른다고 말하는가?
2. 후기가 없는 좌석을 물었을 때 가까운 근거와 한계를 분리해 설명하는가?
3. 숨김 처리된 리뷰를 답변 근거로 쓰지 않는가?
4. 질문이 너무 모호할 때 추가 조건을 물어보거나 범위를 제한하는가?
5. source가 부족한데도 단정적인 추천을 하지 않는가?

## 로그 확인 포인트

RAG 호출 후 다음 테이블과 필드를 확인한다.

- `rag_query_logs.question`
- `rag_query_logs.filters`
- `rag_query_logs.source_ids`
- `rag_query_logs.answer_preview`
- `rag_query_logs.latency_ms`
- `seat_review_embeddings.metadata`
- `seat_review_embeddings.document_version`

이 로그를 모으면 "질문은 맞았는데 source 선택이 틀린 문제"와 "source는 맞았는데 답변 생성이 틀린 문제"를 분리해서 볼 수 있다.
